# Reproducibility and release sequence

The release is intentionally staged so final evidence cannot influence model
choice.

1. Install the Python 3.12 lock and the package without dependency resolution.
2. Acquire the exact official snapshot and review its first-pin manifest.
3. Build and audit deterministic processed tables and the fold manifest.
4. Commit the source pins, schemas, features, candidates, metrics, selection
   rule, and report contracts.
5. Run development selection and the confirmation gate; persist the frozen
   decision and commit it.
6. From a clean tracked commit, execute the locked test once.
7. Validate row-level ranking hashes, generated reports, target-free serving
   artifacts, installed-package inference, API/dashboard flows, and container
   operation.
8. Commit release evidence, push the exact SHA, and require green remote CI.

Raw inputs and processed build files are local and ignored. Public release
assets are derived, attributed, compact, and independently integrity checked.
An acquisition refresh or any change to features, judgments, candidates,
selection, or metrics creates a new experiment version; it never overwrites v1.

Exact commands will be generated by the final Makefile and CLI. Until the v1
artifact exists, smoke tests must fail clearly when `--require-artifact` is used
and may skip only where the test is explicitly marked as a pre-release gate.
